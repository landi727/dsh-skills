# 插图风格库

把持久条目作为事实来源，把索引作为检索入口；技能只保留流程和定位信息。

## 定位与读取

1. 使用 `openai-library:library` 技能访问持久文件，沿用其当前工具、身份与版本规则。
2. 在当前账号按精确文件名定位使用入口 `插图风格库_使用入口.md` 与索引 `插图风格库_索引.json`，并核对它们对应 `/插图风格库/插图风格库_使用入口.md` 与 `/插图风格库/插图风格库_索引.json`。定位后沿用工具返回且已核实的文件标识直接读取。入口暂不可读时按名称和路径重新定位，不能因此另建同名库。
3. 维护范围、字段和状态以当前入口、实际索引和条目为准；`records/ISL-*.json` 是事实源，风格卡、索引与视觉目录由 `scripts/render_catalog.py` 派生。跨对话按索引中的条目文件标识读取，不将整包内相对路径当远程路径。需要回看建库依据时，在该库目录按精确名称定位并读取 `插图风格库_Agent任务指令.md`。主目录按当前账号中的 `/插图风格库/` 路径发现；文件与目录标识均以当前账号下工具返回且已核实的值为准。
4. 入库或修订前阅读 [归档与选择约束](references/record-contract.md)。只读选择无需加载全库正文。

## 完整分析后归档

用户已授权持续归档有效的完整插图分析。按以下顺序执行：

1. 读取本次完整报告并检查对应原图。优先复用原图、原报告现有持久标识，保留原文件原位；新附件尚无持久身份时按当前文件规则保存。对本轮 imagegen 输出遵循自动保存规则，不为归档重复下载或上传；暂缺持久标识时记录待补引用。缩略图只供浏览。
2. 按原图持久标识或文件哈希查重，核对分析版本和来源关系。相同来源更新既有条目；新编号沿用实际索引规则，避免重用旧编号。只有题材、名称或颜色相近不能合并。
3. 保留完整原分析，另提炼风格卡。把原图角色、道具、情节及构图实例与可迁移规则分开；不把固定布局默认为整个画风。标明规则证据和适用推断。
4. 分别写来源完整度、分析核验、生图验证与用户评价。只有摘要、缺原图、配对不明、存在未解冲突的材料进入待补记录，排除自动选择；不得补写成“历史原文”。重新分析时写明本次日期。
5. 先保存条目及来源，再同步索引和入口中的必要导航；修订使用同一持久文件身份并保留版本。每次写入检查返回结果；版本冲突时重读并合并，不能强制覆盖。
6. 检查编号、文件引用、独立状态和可选用标记一致；确保原图与完整规则可一起取回。重复入库不得产生同义条目。

多个 Agent 可并行搜集候选，仅由一个写入者分配编号并更新索引。失败时保留已完成条目，说明未保存或未同步部分；不能将半成品标为可选用。

## 根据创作需求选择

1. 先遵循用户指定风格、参考图和项目已确认风格；本库不得自行替换这些约束。
2. 未指定时提取用途、情绪、主体或场景复杂度、文字量、画幅与制作限制。先读索引筛选，排除资料不足、撤回、明确冲突和不适合当前约束的条目。
3. 读取候选的完整条目、原分析或蓝图，以及实际原图。不能只凭标题、标签、缩略图或搜索摘要选定。以证据充分程度和需求匹配为依据，用户评价按其确认范围使用。
4. 需要随机时仅在合适且可选用的候选内随机；只有一个合适条目时如实说明。没有匹配时说明库的覆盖缺口，按任务现有授权另找参考或探索，不强套条目。
5. 输出选中编号、名称和一句理由，将原图、完整绘画规则、可变范围与限制交给 `execute-illustration-blueprint` 或用户指定执行流程。分析通过不能说成生成已验证。

归档、补录、匹配与只读检查均不得触发生图。实际生成须有当前创作任务授权；其结果和用户评价分别追加，不能自行填写认可。

## 完成与边界

- 说明已归档或选用的条目及具体缺失；保存失败就明确说明，避免把本地文件说成持久可用。
- 保持当前库索引与条目一致；不复制全库进技能或会话记忆。
- 仅在技能被加载时执行以上规则；不承诺跨对话必然触发或后台持续维护。
