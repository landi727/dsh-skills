# Film Review from Transcript（口述稿 → 影评成文）

**类型**：Workflow（Writing/Content Production 方向第一个完整工作流）
**Input Contract**：口述稿/聊天记录/观影笔记（≥1 份，不足则红灯流程）+ 可选的成稿要求（篇幅/平台）。
**Output Contract**：成稿 + 台账摘要；完整 Opinion Map / Voice Profile / 台账默认留档，用户索取再给。
**Responsibility**：把用户已有的口述/聊天/笔记整理成影评——提升结构与书面表达，观点、判断方式与个人语言特征全部属于原作者。成稿应像"用户自己想完，优秀编辑帮整理"。
**Boundary**：不研究电影资料、不发明观点/主题/象征/社会意义/哲学升华、不写通用文章。**例外**：用户明确指称但记不清的客观事实（人名/片名/术语），允许查证补全并在台账标注。体检与提问纪律遵循 no-slacking；"成稿成什么样"说不清时转 im-satisfied。
**Stop Condition**：Critic 三查通过且台账完成即交付；用户改稿时单轮只改对应项（no-slacking R5）。
**Reuse Scope**：影评/观后感成文；书评待真实验证后再扩展。Opinion Map、Voice Profile、Edit Ledger 为跨领域候选能力（见 WORKFLOW-RETROSPECTIVE）。

## 核心铁律（违反任何一条即失败）

1. **观点属于用户**：输入材料是观点事实源。禁止为"完整/深刻/专业"补写用户没表达过的任何观点、主题、导演意图、象征、社会意义、哲学升华、价值判断。允许补的只有语言连接。
2. **先理后写**：禁止拿到口述稿直接全文重写。先做 Opinion Map（用户到底说了什么），再做结构（怎么成文）。
3. **最小必要编辑**：能删减/合并/调序解决的就改这些；原句能用不重写。
4. **成稿像"用户想完、编辑整理"，不像 AI 写的。**

## 流程（六步）

### Step 0 · 材料清点（只登记，不重写）
- 列出全部输入单元（口述段/聊天/笔记），标注类型与先后。
- 材料缺失或不足以成文 → 按 no-slacking 红灯流程给可达性报告（缺什么 / LIMITED GO），不硬写。

### Step 1 · Opinion Map（观点图，核心中间物）
逐条提取用户**实际表达**的内容：
```
【观点 N】主张/判断（立场强度：断言 / 倾向 / 犹豫）
   依据：原句引用（可删口头废话，不改含义）
【未解决】用户自己留下的疑问/摇摆（原样保留，不许改成结论）
【未表达】本次材料里用户没有说的主题（明确列出，防止补写）
```
- 立场强度如实标注：强断言 / 有条件 / 犹豫 / 中途反悔。
- 矛盾与思考变化是内容，不是错误——保留。

### Step 2 · Voice Profile（声音档案，内部三层）
从材料提取（清单见 `references/voice-markers.md`）：
1. **Thought Signature（思考特征）**：判断方式、犹豫、自我修正、观点力度——**必须保留**。
2. **Authorial Voice（作者声音）**：词汇、节奏、句型、表达偏好——保留并适度书面化。
3. **Speech Noise（口述噪声）**：填充词、口吃、转录习惯（"就那个/然后然后/哦对"）——**默认清理**。**口语脚手架**（"我觉得/我有一个感受/这也是我强烈的感受"）同样默认清理：书面成稿转直接断言，作者的判断姿态由断言本身呈现。
另提取：**高价值原句清单**（尽量原样保留）与**禁用语清单**（见 `references/anti-ai-patterns.md`）。

### Step 3 · Article Shape（结构设计）
- 结构必须来自 Opinion Map 中观点的关系（自然推进顺序、矛盾放哪、疑问保留与否），**禁止套三段论模板**。
- 输出：一段 Shape 说明（为什么这个顺序属于这份材料）+ 骨架。
- 结构形态对照视野见 `references/shape-catalog.md`（用于防止只会一种结构，不是从中挑选套用）。
- 用户原话适合做开头/转折时，优先用原话。

### Step 4 · Draft（起草）
- **优先最小编辑**：能靠删重复/断裂、合并同义、调序解决的，不改句子。
- **允许必要重写**：段落不重写就无法成文（句子组织混乱、口语碎片拼不成段）时，允许整段重写——但必须满足：观点不变、立场强弱不变、不新增判断、高价值原句保留、重写内容可追溯到原稿对应句。
- **观点先行**：段落内判断在前、依据在后；除非材料自然形态另有要求。
- **承接纪律**：口述是想到哪说到哪，成稿必须逐段可承接——衔接句的"意思"必须来自 Opinion Map，禁止为衔接发明观点。
- 禁止：统一节奏、把每个观点写得同样完整、借重写悄悄调整立场。
- 犹豫、未决、矛盾保留。
- 每处新增/改写/重写都记入编辑台账。

### Step 5 · Critic（三查自检 + 编辑台账）
1. **观点保真查**：对照 Opinion Map 逐条核对——无新增观点、疑问没变结论、立场强度没变、"未表达"没被补写。
2. **Voice 查**：对照 Voice Profile——Thought Signature 与 Authorial Voice 是否保留、Speech Noise 是否清理、高价值原句保留情况、禁用语是否出现。
3. **Anti-AI 查**：对照 `references/anti-ai-patterns.md`——模板开头/过度总结/虚假升华/金句制造/高频套话；做一次 Horoscope 测试（去掉作者身份与片名，这段话是否"任何人写任何人"都成立？）。
- 输出**编辑台账**：删了什么、并了什么、调了什么、补了什么连接、改写了什么 + 每处原因。
- 查不过 → 回 Step 4 定向修改，只改对应项。

### Step 6 · 交付
- 遵循 no-slacking Internal by default：展示**成稿 + 台账摘要**（几行）；完整 Opinion Map / Voice Profile / 台账默认留档，用户索取再给。
- QA 结论属判断依据（no-slacking R4）：说"保真通过"必须带具体核对结果，不许"感觉挺像"。

## 失败处理
- 材料缺失/过少：no-slacking 红灯流程，不硬写。
- 用户要求"帮我升华/拔高一下"：说明边界（铁律 1），或按 im-satisfied 先立"允许补写的范围"再执行。
- Critic 两轮不过：停下报告"哪项未过 + 已修尝试"，不无限改。

## 链
- 上游：no-slacking（体检/全局提问上限）→（成稿标准说不清时）im-satisfied
- 下游：用户（成稿 + 台账摘要）
