# Film Review from Transcript（口述稿 → 影评成文）

**类型**：Workflow（Writing/Content Production 方向第一个完整工作流）
**Input Contract**：口述稿/聊天记录/观影笔记（≥1 份，不足则红灯流程）+ 可选的成稿要求（篇幅/平台）。
**Output Contract**：成稿 + 台账摘要；完整 Opinion Map / Argument Architecture / Voice Profile / 台账默认留档，用户索取再给。
**Responsibility**：把用户已有的口述/聊天/笔记整理成影评——观点、判断方式与个人语言特征全部属于原作者，同时真正完成一篇影评的结构与论证：**不抢走作者，但要当优秀编辑**。
**Boundary**：不研究电影资料、不发明观点/主题/象征/社会意义/哲学升华、不写通用文章。**例外**：用户明确指称但记不清的客观事实（人名/片名/术语），允许查证补全并在台账标注。体检与提问纪律遵循 no-slacking；"成稿成什么样"说不清时转 im-satisfied。
**Stop Condition**：Critic 四查通过且台账完成即交付；用户改稿时单轮只改对应项（no-slacking R5）。
**Reuse Scope**：影评/观后感成文；书评待真实验证后再扩展。Opinion Map、Argument Architecture、Voice Profile、Edit Ledger 为跨领域候选能力（见 WORKFLOW-RETROSPECTIVE）。

## 核心铁律（违反任何一条即失败）

1. **观点属于用户**：输入材料是观点事实源。禁止为"完整/深刻/专业"补写用户没表达过的任何观点、主题、导演意图、象征、社会意义、哲学升华、价值判断。允许补的只有语言连接与论证组织。
2. **先理后写**：禁止拿到口述稿直接全文重写。先做 Opinion Map 与 Argument Clustering，再动笔。
3. **最小必要编辑保护的是作者的思想和声音，不是原稿的句子结构**：允许重组段落、合并口述片段、调整论证顺序、必要时重写句子；严禁新增观点、改变立场强弱、替作者完成他没有完成的思想跳跃。
4. **成稿要像"用户想完、编辑帮整理"，并且是一篇完整的影评，不是整理好的观影笔记。**

## 流程（七步）

### Step 0 · 材料清点（只登记，不重写）
- 列出全部输入单元（口述段/聊天/笔记），标注类型与先后。
- 材料缺失或不足以成文 → 按 no-slacking 红灯流程给可达性报告，不硬写。

### Step 1 · Opinion Map（观点图 + 论断强度）
逐条提取用户**实际表达**的内容：
```
【观点 N】主张/判断（立场强度：断言 / 倾向 / 犹豫 / 中途反悔）
   依据：原句引用（可删口头废话，不改含义）
【未解决】用户自己留下的疑问/摇摆（原样保留，不许改成结论）
【未表达】本次材料里用户没有说的主题（明确列出，防止补写）
```
- 每条观点标注**论断强度**：Observation（观察）/ Interpretation（解读）/ Strong Claim（强判断）/ Speculation（推测）/ Question（疑问）。
- **Strong Claim 必须过 Claim → Evidence → Interpretation 检查**：证据撑不住的，降级或明确标注为作者推测——禁止为了"忠实"把随口推测升格成文章事实。
- 矛盾与思考变化是内容，不是错误——保留。

### Step 2 · Argument Clustering（论点收束）
在 Shape 之前回答：**哪些观点属于同一个更大的论证？** 产出：
- **Thesis（核心命题）**：材料里那个能统领全文的中心判断；
- **一级论点**：支撑命题的几条主要论证；
- **证据**：哪些局部观察服务于哪条论点；
- **旁支**：有价值但不服务主线的（轻处理或舍弃，记入台账）；
- **Tension（张力）**：材料里的内在矛盾（若有）——它决定结尾。
禁止让多条不错的判断并排站成一篇文章。

### Step 3 · Voice Profile（声音档案，内部三层）
从材料提取（清单见 `references/voice-markers.md`）：
1. **Thought Signature（思考特征）**：判断方式、犹豫、自我修正、观点力度——**必须保留**。
2. **Authorial Voice（作者声音）**：词汇、节奏、句型、表达偏好——保留并适度书面化。
3. **Speech Noise（口述噪声）**：填充词、口吃、转录习惯、**口语脚手架**（"我觉得/我有一个感受"）——**默认清理**，书面成稿转直接断言。
另提取：**高价值原句清单**（尽量原样保留）与**禁用语清单**（见 `references/anti-ai-patterns.md`）。

### Step 4 · Article Shape（结构设计）
- 结构必须来自 Argument Clustering 的结果（Thesis / Tension 决定骨架），不是观点罗列。
- 结构形态对照视野见 `references/shape-catalog.md`（防止只会一种结构，不是从中挑选套用）。
- 用户原话适合做开头/转折时，优先用原话。

### Step 5 · Draft（起草：允许结构性重写）
- **允许**：重组段落、合并口述片段、调整论证顺序、重写句子。
- **红线**：观点不变、立场强弱不变、不新增判断、关键表达可追溯原稿。
- **观点先行，但段落开头必须多样化**：禁止每段"总起句+冒号+条目"的同构写法；禁止"第一点/第二点"式枚举（除非材料本身如此）。
- **承接纪律**：口述是想到哪说到哪，成稿必须逐段可承接——衔接句的"意思"必须来自 Opinion Map，禁止为衔接发明观点。
- 犹豫、未决、矛盾保留。
- 每处新增/改写/重写都记入编辑台账。

### Step 6 · Critic（四查自检 + 编辑台账）
1. **观点保真查**：对照 Opinion Map——无新增观点、疑问没变结论、立场强度没变、"未表达"没被补写。
2. **Voice 查**：对照 Voice Profile——Thought Signature 与 Authorial Voice 是否保留、Speech Noise 是否清理、高价值原句保留情况、禁用语是否出现。
3. **Anti-AI 查**：对照 `references/anti-ai-patterns.md`——模板开头/同构段落/条目枚举/过度总结/虚假升华/金句制造/高频套话；做一次 Horoscope 测试。
4. **Editorial Check（完成度查）**：全文是否有中心问题？每段是否服务主线？一级论点与证据是否分清？是否有明显旁枝？段落之间是否产生推进？结尾是否完成前文形成的矛盾？
- 查不过 → 回 Step 5 定向修改，只改对应项。
- 台账列明：增/删/并/调/改逐项 + 原因。

### Step 7 · 交付
- 遵循 no-slacking Internal by default：展示**成稿 + 台账摘要**；完整留档备索。
- QA 结论属判断依据（no-slacking R4）：说"保真通过"必须带具体核对结果。

## 失败处理
- 材料缺失/过少：no-slacking 红灯流程，不硬写。
- 用户要求"帮我升华/拔高一下"：说明边界（铁律 1），或按 im-satisfied 先立"允许补写的范围"再执行。
- Critic 两轮不过：停下报告"哪项未过 + 已修尝试"，不无限改。

## 链
- 上游：no-slacking（体检/全局提问上限）→（成稿标准说不清时）im-satisfied
- 下游：用户（成稿 + 台账摘要）
