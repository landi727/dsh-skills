# 插图动效可行性验证

把高风险动态问题缩小为可以运行、比较和检查的小样，再决定正式制作路线。结论只覆盖实际检查的版本、动作、视口和设备。

## 1. 确定任务范围

- 读取当前有效参考、动作说明、代表素材、代码或运行入口，记录版本与来源；过期素材仅作为失败案例。
- 区分“只要规划”“只要诊断”“制作小样”“修复并复验”。只要规划时输出计划，不擅自生成素材或修改实现；已经要求制作小样时，在该范围内直接执行。
- 动作缺少关键目标时先做不依赖缺失项的检查，再列出必须补充的信息；不擅自确定朝向、幅度或最终构图。
- 无法取得源码、素材或运行环境时，完成可观察诊断，标出未验证项。需要哪份图层、原始图、录屏或入口就具体说明来源和用途；不伪造运行证据。
- 静态拆图、遮挡补绘、扩画和尺寸导出交给 `split-illustration-web-assets`。传入由试验得到的覆盖要求，保留其静态工作范围。
- 通用浏览器交互、响应式与运行错误检查复用 `build-web-apps:frontend-testing-debugging`；动画素材标准化复用 `game-studio:sprite-pipeline`。不直接修改插件技能。

## 2. 建立试验合同

复制 [assets/trial.example.json](assets/trial.example.json)，填写真实数据；删除不适用字段，保留未知项并说明原因。

1. 写清目标动作、触发与结束条件、是否循环、可以中断的状态，以及原速回放区间。
2. 标出起始姿态、预备动作、运动极值、遮挡交换、结束姿态；转身需包含身体、头、耳朵、衣物等真实朝向变化。
3. 划定随动对象、应固定对象、允许影响区与禁止影响区；记录颜色、服装、毛色分区等身份锚点。
4. 列出目标视口、屏幕像素比、设备与浏览器；若未知，采用明确标注的试验假设，不将其作为用户设备已验收。
5. 从参考或已确认要求确定幅度、时序和质量条件。没有依据时保留可比较候选，不发明统一数值阈值。
6. 选择风险最高且足以代表问题的最小对象；背景覆盖试验仍需包括实际合成背景层组。

阅读 [references/trial-and-dispatch.md](references/trial-and-dispatch.md) 选择路线、派发任务和组织失败定位。涉及转身时，替换素材流程中“保持同一朝向”的规则；保留角色身份、画幅、坐标与锚点一致。整条生成、关键姿态逐帧制作、插帧、骨骼或网格形变均为候选，按小样证据选择。

## 3. 制作最小可运行小样

- 在隔离副本或试验入口中制作，只引入验证本轮假设所需的素材、层级与动作，提供复现入口和控制方式。
- 固定素材、视口、触发路径与时间轴，再比较候选。每次只改变一个关键变量，避免结果无法归因。
- 保留原速回放、暂停或逐帧查看、极值定位和循环检查能力；若正式动作可中断，小样必须复现中断、重触发与恢复。
- 保留源图、导出素材、最终渲染的对应区域，方便定位清晰度问题。低质量占位素材限制判断时明确标注。
- 网页打开、代码编译、帧尺寸一致只能证明各自事项；动态自然、线条稳定与流畅度需要运行证据。

## 4. 检查并形成证据

阅读 [references/motion-checks.md](references/motion-checks.md)，检查本轮相关项目。每个结论附版本、视口、设备或环境、触发步骤、时间点和截图或录屏。

- 先看原速整体运动，再看关键帧和慢放；慢放辅助定位，不代替原速判断。
- 检查关节轮廓与体积、遮挡变化、固定部位、身份锚点、起止与转身连续、循环与中断、背景覆盖、清晰度和作用域。
- 在目标设备与视口检查实际回放，记录观察时长、交互路径和性能采集方法；未经运行的设备保持未验证。
- 自动检测提供缺陷线索；自然感、动作意图、风格和遮挡可信度需要视觉判断。各自写清依据与局限。

### 背景逐像素覆盖检查

复制 [assets/coverage.example.json](assets/coverage.example.json)，填入实际 RGBA 文件、逻辑尺寸、坐标、层组、采样帧矩阵和要求覆盖的视口矩形。所有矩阵必须显式填写。

```bash
python3 "<skill-root>/scripts/check_motion_coverage.py" coverage.json \
  --report coverage-report.json --mask-dir coverage-masks
```

- 将 `<skill-root>` 替换为本技能实际目录；可在项目目录执行。输入文件路径相对 JSON；报告和诊断图路径相对执行目录。输出不得覆盖已有文件或输入素材。
- 脚本用实际 alpha 合成逐像素检查每个已采样状态，不使用边界框替代有效内容。矩阵含义、采样密度和阈值见专项检查参考。
- 退出码：`0` 已采样栅格全部覆盖；`2` 检出未覆盖像素；`1` 输入或执行错误。报告含最差帧和未覆盖区域定位。
- 它不证明连续时间、非线性形变、未来帧或真实渲染器的覆盖；按运动极值和实际交互补采样，并用浏览器运行检查复验。
- 不默认固定边距或三倍尺寸。将实际缺失区域、坐标、视口和运动范围传给静态素材流程；源分辨率、有效内容范围和最终像素需求分别记录。

## 5. 定位失败与受控修改

按“复现 → 判断故障所在环节 → 单一假设的小实验 → 最小修复 → 原条件复验 → 连带检查”推进。连续实验未改善时重新审查路线与素材，避免继续叠补丁。

修改后重新检查身份锚点、固定对象、作用范围、相关视口及同素材使用处。将可复用失败提炼为最少案例记录，保留真实症状、已验证原因、检测方法与证据；推测原因写为待验证。

## 6. 交付结论

为每项条件输出 `通过 / 未通过 / 未验证`，并提供：

- 试验对象与实际运行环境、复现步骤、小样入口、关键证据和检查范围。
- 未通过项的位置、时间点、已定位环节和建议实验；未验证项缺失的材料或环境。
- 需要补齐的遮挡内容、背景有效覆盖区域、逻辑尺寸和目标输出像素需求。
- 候选方案比较、选择依据、正式实现建议与剩余限制。
- 可以直接派发的实施与独立检查任务，继承有效基准与修改边界。

已采样覆盖通过不能概括为全动画通过；技术路线可运行不能概括为质量合格。需要整合进正式网站时，沿用用户授权范围执行，使用通用前端测试技能完成对应检查。
