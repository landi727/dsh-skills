# 装配清单与背景覆盖

## 坐标与尺寸

统一采用原图左上角 `(0,0)`、向右为 x、向下为 y 的一倍逻辑像素坐标。图层文件裁掉空白后，`x,y` 是其左上角在原图的位置，`width,height` 是其完整文件对应的逻辑尺寸，包含有意保留的边距。

记录文件像素尺寸为 `width × export_scale`、`height × export_scale`。例如逻辑 200×100、三倍导出时文件为 600×300，装配仍占 200×100。`x,y` 可以为负数，表示扩展到了原图之外。不要把原图位置重复叠加裁切偏移。

`canvas` 从原图原点开始定义重组区域，宽高不小于 `source`；默认等于原图尺寸。扩画文件保留自身完整范围，静态原图重组可以裁到原图区域。需要查看负坐标扩画时在 `target_views[].source_rect` 中指定查看范围，预览直接从完整图层绘制。

同一分组只提供组织信息。层序使用整数 `z`，从小到大绘制；同 z 按清单顺序绘制并提示核对。同组的多文件不得擅自合并，除非用户要求。

## 场景字段

| 字段 | 约定 |
|---|---|
| `schema_version` | 固定为 `1` |
| `source` | `file,width,height`；推荐记录 `sha256`，源文件路径相对清单目录 |
| `canvas` | `width,height`；一倍逻辑坐标的静态重组尺寸 |
| `layers` | 每项有 `id,file,kind,z,x,y,width,height,export_scale,source_method` |
| `name` | 图层的可选显示名称；省略时使用 `id` |
| `kind` | `background/structure/subject/prop/foreground`；按素材用途选择，不套具体角色 |
| `source_method` | `native/extract/extract-and-complete/regenerated`；重新生成必须如实记录 |
| `visible_source_preserved` | `true/false/unknown`；由原像素、蒙版与人工核查决定，脚本不替代判断 |
| `group` | 可选的静态分组字符串 |
| `completion_mask` | 可选；与图层文件像素尺寸相同，白为补绘允许区、黑为可见原画保留区 |
| `opaque_allowed` | 可选；仅用于合理的完整不透明矩形素材，不能借此掩盖应透明却带底的问题 |
| `resolution` | 可选的逐层尺寸要求；有网站显示要求时必须填写。字段见 resolution-and-export.md；缺失时尺寸适用性标为未验证 |
| `coverage` | 可选的 `mode:'opaque-rect'` 与 `required_rect:{x,y,width,height}`，用于铺满指定区域的背景 |
| `target_views` | 可选；每项 `id,width_px,height_px,source_rect`，声明静态查看范围；宽高是预览输出像素，网页有效 CSS 显示尺寸另填 `resolution` |
| `notes` | 可选；记录近似边界、推断补绘、导出方法及尚未验证项 |

路径保持包内相对路径。不要在清单中放机器私有绝对路径或声称不存在的文件。像素与逻辑宽高采用正整数；坐标可为有限数值，优先整数，避免非整数重采样导致边缘差异。

## 从显示需求确定覆盖矩形

1. 读取已确认的各目标容器尺寸、显示缩放、居中/对齐与 `contain/cover` 或其他裁切方式。
2. 把实际可见区域换算回原图一倍逻辑坐标，得到各视图的 `source_rect`。
3. 按用户或下游提供的左、右、上、下扩展边距扩大相关矩形；对同一背景取这些区域的并集包围矩形作为 `required_rect`。
4. 单独标记负责铺满画面的底层背景；对剪影、云片、幕布等有意留空的装饰层，不要求其铺满整个区域。
5. 对补画完成后的实际导出背景，在矩形内部检查有效不透明内容。透明空白不能计入覆盖。

不根据“之后可能做效果”自行计算动作或设默认百分比。外部没有提供额外覆盖需求时只确认已声明的静态范围，报告未声明范围未验证。

### 静态适配换算

如果原图 `W×H` 按等比缩放显示到容器 `Cw×Ch`：`contain` 的显示比例取 `min(Cw/W,Ch/H)`，`cover` 取 `max(Cw/W,Ch/H)`。容器在原图中的查看宽高为 `Cw/s,Ch/s`。居中时左上角为 `((W-Cw/s)/2,(H-Ch/s)/2)`；其他对齐方式按实际布局计算。

`contain` 会显示原图外的区域；如果设计要求那里也由背景覆盖，则需为这些区域补画或使用已确认的纯色背景。不要将透明剩余区域默认为合格。`cover` 的裁切可能满足底图覆盖但裁掉主体，需要另做主体裁切检查。

### 扩展边距示例

仅作为明确边距的素材例子：查看范围 1440×900，指定左右各补 60、上下各补 30，则 `required_rect={x:-60,y:-30,width:1560,height:960}`。若该背景三倍导出，像素为 4680×2880，装配位置仍为 `(-60,-30)`。这组数字不能自动套到其他任务。

## 补绘蒙版与保留区

为每个补齐图层保留与文件同尺寸的灰度蒙版；白区为许可生成补绘区域，黑区为原画保留区域。把生成结果用于白区前，核对补绘与原轮廓衔接。需要柔边时记录过渡带并人工检查，不宣称所有半透明像素均逐像素保留。

蒙版存在只证明记录了区域；它不证明生成过程遵守了保留要求。应保留可复查的原始提取、补绘候选和最终文件来源；不要求把所有中间候选交付给用户。
