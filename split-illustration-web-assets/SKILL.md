# 插图拆分为网站素材

把已确认的画面转为可重组、可检查、可用于搭建的网站素材。保留确认的设计和可见原画；以用户分组、目标显示区域和素材完整性要求决定拆分与补齐。不要把当前项目的角色、舞台、配色或特定框架作为通用默认值。

## 范围与输入

- 接收原图或原生分层文件、用户指定分组、交付格式和尺寸倍数；复用可用的原始素材。
- 接收目标容器尺寸、屏幕比例、裁切方式及指定扩展边距。已有网站时读取相关的静态布局要求，勿改写网站功能。
- 缺少原图时先索取原图；不要用记忆里的图代替。分组未指定时，根据对象、遮挡与搭建需要给出明确拆层表，并在当前授权内执行。
- 尺寸倍数未指定时保留原生像素母版，按已知显示尺寸准备网页版本；不要默认套用某个项目的三倍规则。用户指定三倍时按三倍导出，并如实标明重采样与新增细节的区别。
- 屏幕或覆盖需求缺失时完成原图范围内的拆分和重组，标明适配/延展尚未验证；不要擅自设定额外边距后称为满足后续全部用途。
- 不输出动作方案、关节、旋转点、动作幅度或动态试验。把用户提供的额外覆盖范围作为素材尺寸要求处理，不推导动效。

## 执行流程

### 1. 锁定来源与拆层表

保留原文件及哈希、原始宽高、色彩配置和坐标原点。列出图层 ID、名称、内容边界、分组、前后层序、提取来源、缺失区域和完整性要求。用户指定的分组优先；确实会损失遮挡结构时说明影响并给出最小调整。

先判断来源：原生分层直接导出；已有独立素材优先复用；扁平图才进入提取与补齐。遮住某物的前景和被遮住的对象分别处理，不把遮挡物粘进后方素材。

### 2. 先检查原素材尺寸

读取 [resolution-and-export.md](references/resolution-and-export.md)。按每层在网站中的最大有效显示宽高和约定的备图倍率计算目标像素；记录放大前的有效绘制像素，排除透明空边，不以整张插图尺寸代替局部素材尺寸。

尺寸不足时优先取得匹配的高分辨率原图或原生层；仍不足时执行当前工具与授权允许的放大路线，保留原生母版并记录方法。无法达到要求时报告失败或未验证，不把改大文件宽高认定为高清完成。目标显示或备图倍率未确定时标为未验证，不默认三倍或声称全部适配。

### 3. 提取可见原画并补齐

读取 [extraction-and-completion.md](references/extraction-and-completion.md)。优先保留原图可见像素；对生成补齐区建立独立蒙版并记录来源。需要生成编辑时遵守当前图像工具的规则和授权，不以代码模拟生成补绘。

按任务要求补全被挡和被裁的部分；用户要求完整素材时补全整个对象。让原有颜色、轮廓、纹理与新补齐区域连续。隐藏区域属于依据原图推断的内容，不称为恢复了不可见的原画。不要整个人物重画后冒充原像素提取。

只做可确认的对象分离；线稿/填色分离不作为本技能模块。无法准确提取的边界说明近似程度，不用颜色阈值删除黑毛、暗部或细线。

### 4. 准备足够的背景覆盖

先区分像素分辨率与内容覆盖范围：放大像素不会自动增加显示时可覆盖的区域。按目标显示、裁切和指定边距计算每层 required_rect，读取 [manifest-and-coverage.md](references/manifest-and-coverage.md)。

需要延展时补出真实连续的背景内容，保留原图内已确认的画面。透明空边、复制拉伸边缘或偷偷放大中心构图不能当作扩画完成。对负责铺满区域的背景，检查有效不透明内容覆盖整个所需矩形；具有刻意透明孔洞的装饰层另行标注。

### 5. 导出与装配数据

输出 RGBA PNG 母版或用户指定的透明格式；按用途导出网页版本，检查线条、颜色与透明度。对每层在 scene.json 中记录 resolution 的目标显示、备图倍率、原生有效尺寸及处理方法；用实际导出 alpha 边界核对目标像素，两轴均满足才能认定尺寸达标。避免把全部高清母版直接作为网页加载版本，记录像素尺寸、逻辑显示尺寸、放大方法和文件大小。

生成 scene.json：用原图一倍坐标记录文件、层序、位置、逻辑宽高、裁切偏移、静态分组、输出倍数、补齐蒙版及覆盖要求。扩画允许负偏移，不把三倍像素尺寸再当作三倍显示尺寸。复制 [scene.example.json](assets/scene.example.json) 作为数据模板，删除未启用的可选字段。

### 6. 静态验收

读取 [static-validation.md](references/static-validation.md)。运行：

```bash
python3 <skill-root>/scripts/inspect_assets.py --manifest <package>/scene.json --out-dir <package>/checks
```

把 <skill-root> 替换为本技能实际目录。脚本需要 Pillow；先检查环境，缺失时优先使用可用的已安装运行时。不能运行时标为未验证，不杜撰检查结果。

使用实际导出文件重组，与原图比较构图、尺度、层序、颜色及边缘。按黑白底检查残色、白边、孔洞、细线与补绘接缝。对每个已声明的屏幕视图和覆盖矩形逐项检查；仅测透明边界框不足以证明覆盖完整。

复制 [preview.html](assets/preview.html) 到交付包。通过文件选择载入包内文件，静态切换图层、原图、差异、黑白底和已声明视图；界面只作静态检查，不播放或设计动效。

像素差异只是证据。完全一致时可以说明精确重组；存在差异时结合源文件、补绘蒙版与视觉检查判定原因。脚本通过不能单独证明角色、画风或补齐合理。分别判定源图尺寸是否足够、导出有效像素是否达标、目标显示下的画质是否通过；画质须检查模糊、锯齿、细线、纹理及放大造成的设计变化，自动尺寸通过不能替代画质验收。

### 7. 交付与失败处理

新包默认组织为 source/、layers/、必要的 masks/、scene.json、静态预览和 checks/；已有包可沿用清楚的相对路径，无须仅为目录名重排。确保源图、全部素材、清单与检查证据齐备。在简短验收结果中逐项写明：已通过、未通过、未验证；标注推断补绘区域、近似提取、重采样和剩余限制。

只修失败素材，保留已通过项。按以下规则完成修复：

- 以用户当前要求和实际验收结果判断完成；一次生成、自动检查通过或打包待修文件均不构成任务完成。
- 在已授权的对象、设计和交付范围内，继续完成失败项的必要修复，包括有明确原因的针对性再生成；用户未限制次数时，不默认仅生成一轮，不因仍有待修项而直接结束。
- 保留“不得私自连续追加生成轮次”的边界：不得自行扩展方案、增加候选数量、改变已确认设计，或在没有诊断和修复目标时反复生图。每次修复先定位缺陷、调整操作或提示词，再检查实际结果；相同问题反复出现时重新判断路线，勿盲目重复同一方法。
- 遵守用户明确指定的次数、费用或工具限制；用户明确删除或改写旧偏好时，以最新指令为准。确实触及明确限制或需要超出当前授权时，先完成不受限的工作，再说明具体待修内容、阻碍和所需下一步授权，不把限制解释为已完成。
- 完成全部已确定要求及相关验收后再交付成品；遇到真实工具失败、能力缺口或明确限制时如实报告未完成部分及已尝试的修复，保留可回溯结果，不把待修包当作成品。

保存到当前环境要求的持久位置；已有网站项目的素材按用户授权放入对应项目。不自动开始网站搭建，不安装外部分层模型，不交付未经核验的示意素材作为成品。
