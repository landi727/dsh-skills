# 证据、抽帧和合同

## 抽帧脚本

要求 Python 3、ffmpeg、ffprobe 和 Pillow。脚本用参数数组调用子进程，支持路径中的空格和 shell 特殊字符。缺依赖时明确失败，不自行安装。

```bash
# 按本次事件长度选择初看采样密度；示例值不作为统一标准。
python3 "<skill-root>/scripts/extract_motion_frames.py" --video reference.mp4 --out-dir overview --fps 2

# 检查快速区间的全部原帧。
python3 "<skill-root>/scripts/extract_motion_frames.py" --video reference.mp4 --out-dir detail --start 2.1 --end 2.8 --all-frames --max-frames 500
```

将 `<skill-root>` 替换成当前技能实际目录；输入与输出路径按任务替换。`--fps` 和 `--all-frames` 必须二选一。`--start` 默认 0，`--end` 默认视频末尾，均相对第一视频帧；右端不包含。输出目录必须不存在或为空。脚本预先检查数量，原帧输出数或请求采样时间槽超 `--max-frames`（默认 1000）直接失败；不会自动缩减数量。`--fps` 按目标时间选最近原帧，不插值、不复制图片；多个目标落在同一原帧时在 manifest 保留所有采样时间并给出提示。需要看到每一帧时使用 `--all-frames`。

输出：

- `frames/frame-000001.png`：原尺寸解码图，不裁切或重绘，保留输入文件。
- `contact-sheet-001.jpg` 等：按顺序的缩略联系表，标注源帧索引与相对时间；联系表不可用于边缘、纹理和像素精度检查。
- `manifest.json`：输入相对路径和 SHA-256、视频元信息、采样设置、输出路径及逐帧时间。所有产物路径相对 manifest 所在目录。

源时间字段含 `source_pts_time_seconds`（容器原 PTS，可为空）、`source_best_effort_pts_time_seconds`（解码器估算 PTS）、`timestamp_kind`（实际采用哪类时间），以及相对首帧的 `source_time_seconds`。`sampling_target_times_seconds` 是请求采样的时间列表；全部原帧模式为 `null`。不得将目标采样时间当作实际帧 PTS。

`avg_frame_rate`、`r_frame_rate` 是源元数据中的帧率；`pts_intervals` 描述解码帧时间间隔及是否变化。VFR 录屏按时间戳分析，不能用“帧数÷固定 fps”推算动作时长。无可靠 PTS、时间倒序或提取数量不一致时脚本失败。

脚本不自动旋转，记录旋转/像素宽高比元数据；若原片需要显示变换，分析时显式换算。PNG 是解码后的 RGB 图；HDR、非方形像素或颜色管理异常的素材，不能仅凭此输出确认显示颜色。脚本抽取首个视频流并会读取全片帧时间，长视频需要更多时间和内存；部分错误输出保留用于排查，未成功生成 manifest 时不作为有效证据包。

## 证据级别

| 类别 | 足够的依据 | 常见误判 |
| --- | --- | --- |
| 观察 | 指定帧、时间区间、录屏中的输入或直接运行状态 | 单张截图证明完整动作、稀疏采样证明没有闪帧 |
| 源码确认 | 同版本源文件、配置与必要运行对照 | 看到某库依赖就断言该效果由它实现 |
| 技术推断 | 可观察特征与可替代机制的比较 | 从弹性外观直接确定物理模型 |
| 未验证 | 明确缺少的输入/视口/版本证据 | 以默认数值或想象补齐 |

对鼠标效果记录轨迹、速度、停留、离开；对滚动记录起点、方向、速度和页面位置；对自动动画记录加载完成条件和播放起点。录屏无可见输入时只记录画面响应，触发原因保留不确定。

## 合同字段的用途

从 `assets/motion-contract.example.json` 复制任务实例。示例采用刻意为空的测量值，便于避免把默认零写成结果。它是输出模板，不是已完成的分析或 JSON Schema。

- `sources`：精确版本/哈希、输入相对路径、源帧率、尺寸与时间基准。远程输入保存原 URL 和采集条件；无法计算哈希时填空并写原因。
- `capture_conditions`：视口、DPR、缩放、页面位置、输入轨迹/速度；未知可空。
- `analysis_coverage`：实际看过的全程与密集区间；记录低帧率或压缩导致的观察限制。
- `effects`：一个 ID 对应一个可独立复现的效果；对象相位和遮挡仍保留其真实依赖。
- `measurements`：数值、单位、测量方法、证据、误差及状态。没有数据填空；不能把“未观察到”推成 0。
- `implementation_candidates`：推断、已确认信息与待验证实验分开。
- `acceptance`：同触发、同视口的重放步骤；时间对齐锚点、极值和过渡检查、允许偏差、证据形式。验收不能仅比初始与终止截图。
- `agent_task`：可改范围、前置输入、产物和完成条件；缺少依赖时报告能完成和无法完成的范围。

尺寸与幅度用本任务实测值，不套用网站、角色或固定倍数。判断背景覆盖需要运动极值和视口裁切；静态拆分使用这个范围补画，运行验收再检查结果。循环和中断没有证据时保留未验证，即使效果看起来能循环。
