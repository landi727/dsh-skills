# 文档合同与同步规则

保留现有文档格式。以下字段只补到足以支持本轮行动的程度；一个文件可承担多个职责，避免重复抄写。

## 共同要求

- 说明用途和适用项目或模块；在容易混淆时注明版本或绝对日期。
- 明确有效、提案、待决、待验证或历史身份；同一文件可有不同状态的条目。
- 引用真实来源、确认依据或证据；缺少依据时写未知或假设。
- 指定同类信息的主要维护位置，并通过链接连接其他职责。
- 明确哪些变化触发更新；让信息能够指导动作或判断。

## 各职责的最低合同

| 职责 | 必要内容 | 不要混入 |
|---|---|---|
| 目标与需求 | 目的、使用者、范围、结果、关键行为和约束；失败或恢复要求按需要补充 | 未确认功能、进度结论 |
| 验收标准 | 来源要求、具体对象、检查动作、可观察结果；审美目标配有效参考和关键对照维度 | 预填的通过结果 |
| 方案 | 对应要求、实现或制作方法、依赖、关键取舍、验证安排、重要未知 | 脱离项目的通用技术清单 |
| 执行任务 | 来源、动作或成果、必要依赖、完成条件、成果或证据位置 | 只写“优化一下”的模糊待办 |
| 进度 | 实现状态、验证状态、证据、阻塞或下一步、必要更新时间 | 无依据的完成百分比或预期当事实 |
| 视觉验收 | 有效参考、检查区域或动作、实际对照图或录屏、差距、结果 | 用静态图证明运动和交互已通过 |
| 决策 | 日期或编号、确认内容、来源与理由、影响、替代关系、状态 | 聊天全文、所有临时尝试、编造的决策理由 |
| 入口 | 目标与阶段短说明、有效要求与参考、成果入口、进度与验收入口、历史指针 | 大段重复规格、旧规则与现役要求混写 |
| Agent 规则 | 开工读取顺序、稳定边界、核实过的运行或检查方式、更新触发条件；链接当前工作范围 | 整套产品需求、当前进度流水账、固定化的本轮临时停点 |
| 接续材料 | 当前成果、断点、未完成项、继续条件、必要授权与资料位置 | 每轮复制完整历史、无关项目资料 |

## 状态与证据

分别表达要求确认、方案确定、实现完成、检查通过、用户验收和发布状态；沿用项目既有词汇，并说明容易混淆的状态。验证为“未验证、部分验证、通过、未通过”等，按条目记录；阻塞原因单独写。

为重要证据注明来源和适用范围：直接运行、本地模拟、预览、生产、真实文件或用户确认。历史证据可以引用，但要注明日期或版本；只读查询不能证明写入或恢复，模拟响应不能证明真实模型质量。要求、参考或相关实现变化后，判断旧证据是否仍适用；受影响而未重新检查的项标为待验证，保留旧结果的历史身份。未受影响的有效证据继续沿用。

进度表可采用：

| 成果或任务 | 实现状态 | 验证状态 | 证据入口 | 阻塞／下一步 | 更新时间 |
|---|---|---|---|---|---|

视觉表可采用：

| 检查项 | 有效目标／参考 | 检查动作 | 实际证据与差距 | 结果 |
|---|---|---|---|---|

无实际检查时填写“待验证”。通用视觉建议不得覆盖用户确认的艺术构图和动效要求。

## 变更的影响检查

| 事件 | 首要维护位置 | 需要检查的关联位置 |
|---|---|---|
| 确认目标、范围、功能或参考变化 | 当前有效要求或参考；决策保存理由与替代关系 | 方案、任务、验收标准、入口 |
| 确认关键实施取舍 | 方案；重要选择进入决策 | 任务、约束、检查方式 |
| 完成实现或制作 | 任务与进度 | 成果入口、相关待验项 |
| 获得检查结果 | 证据与验收 | 进度、缺陷、补救任务 |
| 发现阻塞或未决问题 | 相应任务或待决项 | 推进条件、受影响的方案 |
| 改变稳定工作规则 | AGENTS.md 或项目既有规则 | 入口指针和适用目录 |
| 阶段收束或接续 | 进度与成果入口；必要接续记录 | 决策、有效依据、剩余项 |

确认重要变更时，把其记录与关联修订作为同一轮工作完成，并检查受影响的验收状态是否需要重新验证；顺序可以因现有文件结构调整。无法同步的部分明确列为未完成，避免出现只在日志里生效的要求。

## 保存与交付检查

写入共享文档前核对最新内容或版本，合并并行产生的有效更新；不从旧快照整篇覆盖。无法解决的冲突列为待决，保持相关证据与双方修改可追溯。

核对新旧要求是否有清楚的替代关系，现役引用是否仍指向有效文件，任务是否有执行与检查条件，状态是否有相应证据。检查相对链接时按所在文件目录解析；远程或资料平台链接没有访问条件时注明未核实。

没有可写项目时可以提供内容草稿；明确区分草稿交付与已保存到项目。遵守现场持久化和项目存储规则，不创建第二套无法同步的文档副本。
