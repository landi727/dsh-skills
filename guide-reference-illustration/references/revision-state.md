# 修改基准与版本

## 明确本轮状态

为当前修改保留以下紧凑记录，可留在工作上下文；需要跨会话保存时写入用户已有项目记录，不修改技能来保存项目状态。

| 项目 | 记录内容 |
|---|---|
| 修改底图 | 用户指定的唯一图片或明确版本及其可访问引用 |
| 参考依据 | 仍然有效的身份、画风等参考图及用途 |
| 本轮改动 | 本次新增、替换或删除什么，以及作用范围 |
| 保留要求 | 与本次修改相关且仍有效的身份、画法、视角、构图、色彩或其他内容 |
| 已作废内容 | 仅记录本轮容易误继承的旧要求或旧版本内容 |
| 结果状态 | 新结果引用；检查结论；用户是否确认 |

选择底图的顺序：用户本轮明确指定的版本优先；否则使用对话已明确的当前修改对象。上下文不足以区分多个候选时询问，不擅自选最新生成图。“最新生成”“已检查”“用户认可”是不同状态。

用户说“回到 V2，只改头发，后面的眼睛和服装不要继承”时，从 V2 建立新分支，只加入本轮头发要求；不要把 V3、V4 的改动重新带回。其他仍有效且不冲突的要求继续保留。

用户明确改变某项已确认要求时更新该项，无需重复要求确认；不能把这次变化扩大到其他项目。处理真实冲突时先说明受影响的要求，不默默放弃它们。

## 生成与回查

1. 把正确底图传给编辑工具，同时提供必要的画风或身份参考；不要仅根据旧文字重建全图。
2. 用简短说明表达本轮变化及相关保留要求。多处互不干扰的小改动可合并；容易互相影响时分步处理，先后顺序由依赖关系决定。
3. 比较修改目标是否达成，再比较指定不变项和周围区域是否漂移。局部放大用于细节，全图对照用于构图、视角和整体画法。
4. 未改对或出现意外变化时标为候选，保留原底图和较好版本。需要继续时，在授权范围内选择更合适的底图及方法，不自动把失败候选当作新基准。
5. 依当前任务授权决定继续或交付。不得自行开展额外一轮；已明确授权持续修正时继续推进，直到要求满足或存在可说明的真实阻塞。不要把自己检查通过记为用户已确认。

只输出影响用户判断的改动、检查结果和未解决问题。不要每轮重发全部历史要求，也不要把过去全部修订累积进提示词。
