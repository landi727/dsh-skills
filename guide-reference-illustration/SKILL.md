# 插图·参考图生图与迭代

## 停用状态

用户于 2026-10-15 明确要求停用本技能。禁止自动匹配、显式执行、手动调用，或通过其他技能与 Agent 间接启动。即使收到引用本技能的生图任务，也不得执行以下归档流程；只有用户明确要求重新启用本技能后，才可恢复。

以下原始内容与配套资源仅供管理、审查和未来恢复时查阅，不构成当前可执行指令。

## 原始规则归档（停用期间禁止执行）

## 工作原则

- 让原始参考图直接参与生图；只补充当前目标中容易误解、互相冲突或已有结果确实偏离的要求。信息已经明确时直接执行，允许不增加风格描述。
- 保持分析简短。不要先穷举整幅图、生成完整蓝图、填写固定比例或重复模型可直接看见的内容。
- 以用户本次明确要求为准，继承同一任务中仍有效的已确认要求；原图用于核对视觉事实，历史分析仅作线索。用户纠正后更新有效要求，删除失效描述。
- 将观察、推断和创作建议分开。未确认的推断不得变成硬性约束；单次任务的禁用颜色、留白比例、角色尺寸不得升级为通用规则。
- 独立执行本技能。不要启动或依赖已停用的技能，也不要为本任务修改它们。

## 1. 确定本轮任务

先从当前对话提取目标、实际可用图片、输出数量、用途、尺寸或比例、当前授权范围。不要重新询问已知信息。

- **单张新图：**执行下述共同步骤。只有相关维度存在歧义或出现偏差时，读取 [视觉适配与核对](references/visual-adaptation.md) 的对应条目。
- **多方案：**额外读取 [多方案处理](references/batch-variants.md)。区分不同画风探索与同一画风内的方案变化。
- **连续修改：**额外读取 [修改基准与版本](references/revision-state.md)。批量修改时可与多方案规则组合；修改模式决定底图和保留项，多方案规则决定各版本的差异。

用户只要求分析、建议或检查时，只交付这些内容。用户要求生成或修改时，在已授权范围内继续执行；不把准备说明当成最终交付。没有额外授权时，不自行增加第二轮生成；“继续修改到合格”等明确要求已授权迭代，不应每轮重复请示。只在关键图片缺失或互相冲突的要求无法合理解决时提出必要问题。

## 2. 分配图片职责

查看实际图片，并用稳定编号、文件名或可访问引用标识各图。按本次任务标注它提供的是角色身份、绘画方式、服装、构图、配色还是编辑底图；一图可有多个职责，不要求凑齐所有类别。

对角色任务，明确三类信息：

- **身份：**用户要求保留的形体、花纹、五官、体型关系等辨识特征。
- **画法：**造型概括、线条、填色、光影、纹理等表现方式，以指定画风图为依据。
- **本次设定：**拟人化程度、服装、动作、道具和场景，以本次要求为依据。

保留身份时不要自动锁定旧画法与服装；换画风时也不要抹去必要的身份特征。只改变用户允许变化的维度。多图冲突时按已明确的职责取舍，无法从任务判断的重要冲突才向用户询问。

图片不可见时，不用旧报告或记忆假装完成看图。可先整理已知要求，并指出完成视觉判断还缺哪张图。

## 3. 补充必要的目标适配

明确新图画什么、保留什么、改变什么。仅对影响结果的差异补充可执行说明：新对象如何使用参考画法，角色与场景如何统一，动作和道具如何形成合理关系，以及画面重点、前后层次、疏密如何服务用途。

将“有呼吸感”“不要 AI 感”等模糊反馈对应到实际可见的问题，再给针对性改法。不要默认增加装饰、毛发、材质、几何块或光影，也不要把所有任务统一成低细节、无纹理或大留白。用户要求参考画风并重新设计内容时，明确哪些场景、构图或元素需要重新安排；不能仅改色或替换角色后声称完成新设计。

默认形成一小段生成补充，内容按需要包括：

> 参考图职责；本轮目标；必要保留项与变化项；少量适配说明；交付规格。

只保留会改变执行选择的信息，不必显示内部清单或输出长篇分析。关键要求较多时保留必要信息，不为追求短而遗漏用户约束。

## 4. 执行与检查

将相关原图及编辑底图真正传给当前图像工具，按工具实际支持的方式标识图片；不要仅传文字总结，也不要把其他方案的参考图混入本方案。遵循当前工具的图片输入、透明背景和尺寸规则，不假设某个 API 参数、模型、遮罩或精确尺寸控制在当前环境可用。用户明确指定代码或其他制作方式时尊重其要求。

查看实际输出后，按任务核对：

- 用户硬要求：内容、角色辨识、数量、文字及可验证的交付规格。
- 视觉结果：与指定参考图的相关画法是否匹配，角色与环境是否统一，构图和动作关系是否成立。
- 任务专项：多方案是否满足约定差异；修改是否达到目标，同时保持指定不变项。

直接对照参考图、修改底图和用户要求，必要时查看关键局部。不要只对照自己的分析，也不要以“整体好看”抵消关键要求失败。区分内容缺失、文件问题和显示问题；无法查看完整结果时标为未验证，不宣称检查通过。

发现问题后说明可见偏差及其影响，在授权范围内选择一次局部修正、返回合适底图或重新生成。避免在已经漂移的版本上不断叠加修正词。同一问题持续出现时改变处理方法，保留较好版本；真实工具或输入阻塞时说明已完成内容和具体阻塞，不虚报成功。

## 5. 交付与边界

按用户要求交付图片、准备说明或诊断结果；简短区分已经生成、已经检查、仍未满足或未验证的部分。满足要求后停止可选扩展，不再自动另做一批。

前期可纳入已知导航留位、裁切范围、后续活动空间等用途约束。拆层补齐、动作设计、动画验证、文字精确排版和网站实现交由相应任务处理；静图合格不代表这些后续环节已通过。

不要承诺像素级不变、完全一致或必然减少返工。需要绝对保留局部像素时，说明应采用能锁定原像素的编辑或合成方式；按当前授权和可用工具执行。验证本技能效果时，用相同参考图、需求、工具设置和生成预算比较直接生图与加入技能的结果，分别看约束满足、画风匹配、修改保持、方案差异和返工量；规则检查通过仅证明流程可用。
